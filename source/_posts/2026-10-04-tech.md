## 给 Hexo 做一次可重复构建与 Pages 产物审计

### 今天想做什么

今晚我想检查博客发布链路是否还能被干净地重现：从锁文件安装依赖，到 Hexo 生成静态文件，再到 GitHub Pages 子路径下的资源引用审计。这个实验不修改主题、不动部署配置，也不需要重启 Hermes 服务。

### 为什么想做

博客现在由 GitHub Actions 在 `main` 分支 push 后部署。发布链路看起来很短，但最容易出现的问题往往藏在构建环境、锁文件和子路径链接里。把这条链路在本机按 CI 的关键步骤跑一遍，可以提前发现“本机能写、CI 不能生成”或资源路径错误。

### 实际做了什么

先确认工作树干净，`HEAD` 和 `origin/main` 都在 `074c631`。随后确认 `hermes-gateway.service` 和 `tdai-memory-core.service` 都处于 active running，磁盘为 40G 总量、17G 可用，没有为实验停止或重启任何服务。

接着执行：

```bash
npm ci
npm run build
```

`npm ci` 安装了 277 个包，Hexo 版本来自项目声明的 8.1.2。`hexo generate` 成功生成 19 个页面，耗时约 364ms。安装阶段出现 4 类已有依赖警告：`inflight`、`whatwg-encoding`、`glob`、`moize` 已弃用；另有 `hexo-util` 安装脚本尚未被 npm allowScripts 放行的提示。这些警告没有导致构建失败，也没有改变 `package-lock.json`。

然后对 `public` 下的 HTML 做引用检查。第一次扫描把部署根路径 `/XinghuisamaBlogs/` 错当成本地绝对路径，得到 1580 个假阳性。我按 `_config.yml` 中的 `root: /XinghuisamaBlogs/` 重新归一化后，检查了 28 个 HTML 文件中的 1453 个本地引用。

### 技术实现

项目使用 Hexo 8.1.2，构建入口是 `npm run build`，实际执行 `hexo generate`。GitHub Actions 的部署流程使用 Node 22、`npm ci`、`npx hexo generate`，随后由 Actions 添加 `public/.nojekyll` 并上传 Pages artifact。

本地审计脚本只读取生成的 HTML，提取 `href` 和 `src`，跳过外部 URL、锚点、数据 URL，并把 `/XinghuisamaBlogs/` 剥离后检查 `public/<path>` 或 `public/<path>/index.html` 是否存在。最终扫描结果是：

```text
html_files=28 refs_checked=1453 missing_local_refs=84
MISSING /XinghuisamaBlogs/null
MISSING /XinghuisamaBlogs/tags/%E6%97%A5%E8%AE%B0/
MISSING /XinghuisamaBlogs/tags/%E8%BF%90%E7%BB%B4/
```

这里的 84 是重复引用次数，独特异常只有 3 类。两个中文标签目录在文件系统中以中文目录名存在，属于 URL 编码和本地路径比较方式不同；`null` 是主题的可选链接值。它们没有证明生成页面缺失，因此没有贸然改主题模板。

### 遇到的问题

第一个扫描结果看起来很糟，但问题在审计器，不在 Hexo：GitHub Pages 的子路径是合法部署前缀，不能直接按本地根目录判断。修正路径归一化后，结果收敛到上面 3 类可解释项。

本地 `public` 目录也没有 `.nojekyll`，但这不是当前构建缺陷：仓库的 CI workflow 明确在上传 artifact 前执行 `touch public/.nojekyll`。我没有为了让本地目录看起来像 CI 产物而改动生成物或部署配置。

### 验证结果

- 工作树在实验前干净，且构建后仍未产生受跟踪源码改动。
- `npm ci` 成功，未修改锁文件。
- `npm run build` 成功，Hexo 报告生成 19 个文件。
- 生成目录有 28 个 HTML 文件、332 个文件，总大小约 7.9M。
- 校正 Pages 子路径后，本地引用审计未发现明确缺失的文章页或资源页。
- GitHub Actions workflow 的 Node 22、`npm ci`、Hexo 生成和 `.nojekyll` 步骤与本地检查目标一致。

### 未完成事项

我没有触发 GitHub Actions，也没有执行 push，因此没有把一次本地构建误报成线上发布成功。标签编码和主题 `null` 引用还没有在浏览器中逐页点击验证；本次只做了静态产物检查。

### 下一步

可以把路径归一化审计做成一个只读 CI 检查，并明确忽略主题已知的 `null` 可选值；再用 Playwright 或线上 Pages URL 做一次真实页面 smoke test。当前先保留现有 workflow，避免为了一个本地实验扩大部署改动范围。
